# 微信小游戏提审前必须完成的核验

## 技术上线闸门

- [ ] 用 **Cocos Creator 3.8.8** 打开 `assets/scene/Entry.scene`，无脚本绑定/资源导入错误；2D UI 与 3D 游戏场景同屏显示。
- [ ] 在微信构建面板选择 Portrait，填写自己的 AppID，完成构建；运行 `node tools/install-wechat.mjs build/wechatgame`。
- [ ] 检查主包在目前适用的大小限制内，启动首帧、首局、循环配乐和全部按钮没有报错。
- [ ] 在至少两种真机（含一款中低端 Android）测试：不要卡顿、不黑屏、不因 WebGL/音频解码失败退出。
- [ ] 两个真实微信帐号完成挑战，并核验好友榜只显示真实数据；新旧日期切换后没有跨天记录串入。
- [ ] 在朋友圈/会话分享可用性方面核实当前微信小游戏分享策略；这个项目只依赖会话分享，分享后不加虚拟奖励。
- [ ] 正确配置广告位 ID：测试完整观看、关闭、中断、无网络、广告库存不足；只有 `isEnded === true` 才加倍装饰碎片。
- [ ] 横竖屏适配、异形屏安全区、应用前后台、内存峰值及过热/掉帧实测。
- [ ] 若启用存档云同步或服务器分数验证，应另行评估用户隐私声明、数据存储与服务端安全性。
- [ ] 账号主体、类目、广告资格、备案和审查资料由真实发布账号核验。

## 原型尚未实测项目

- 编辑器 3.8.8 实际构建和手机渲染效果
- Cocos `SubContextView` 动态添加在某些 SDK/引擎构建配置下的行为
- 公开分享卡封面配置
- 真机音频、微信系统 API 权限和广告接入
- 网络延迟、热更新、低端设备的 draw call 与 GPU 占用
- 对抗客户端作弊的服务端措施

不能把静态代码测试替代上述测试，更不能在平台未审核时宣称“已经上架”。
